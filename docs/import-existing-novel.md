# 导入已有小说到 Webnovel Writer

适用场景：你已有一部写了数万字的小说，希望接入本系统的 AI 辅助创作能力（上下文记忆、实体管理、质量审查等）。

## 前置条件

- 已安装 Webnovel Writer 插件
- 已安装 Python 依赖（`pip install -r requirements.txt`）
- 已配置 `.env`（Embedding + Reranking API Key）

## 总体流程

```
准备文件 → 初始化项目 → 逐章构建索引 → 验证 → 开始续写
```

---

## 第一步：准备文件

### 1.1 章节文件

将所有章节整理为独立 Markdown 文件，命名格式：

```
第0001章-章节标题.md
第0002章-章节标题.md
...
第0032章-章节标题.md
```

要求：
- 章节号 4 位数字，从 0001 开始
- 标题中不含特殊字符（`/\:*?"<>|`）
- 每个文件只包含正文内容，不需要额外元数据

### 1.2 大纲文件

准备两个文件：

**总纲**（必须）：全书主线梗概，包含核心冲突、主要转折点、结局走向。

**卷节拍表**（强烈建议）：已写章节的章纲，每章 1-3 句话描述主要事件。格式参考：

```markdown
# 第1卷 节拍表

## 第1章 - 章节标题
萧炎在家族大比中展现实力，击败对手。引出废柴三年的背景。

## 第2章 - 章节标题
药老首次现身，揭示戒指的秘密。萧炎决定修炼。
...
```

即使是简版章纲也比没有强——这是 Context Agent 的核心输入，没有大纲系统会"失明"。

### 1.3 设定集

在以下文件中填入核心设定（不需要很长，但关键信息必须有）：

| 文件 | 内容 |
|------|------|
| `主角卡.md` | 姓名、性格、能力、初始状态 |
| `世界观.md` | 世界基本规则、地理、势力格局 |
| `力量体系.md` | 等级划分、能力分类、升级规则 |
| 角色卡（可选） | 重要配角的独立设定卡 |

设定集是 Consistency Checker 的校验依据，缺失会导致一致性审查失效。

---

## 第二步：初始化项目

在 Claude Code 中执行：

```bash
/webnovel-init
```

按提示填入书名、流派等信息。系统会创建：

```
PROJECT_ROOT/
├── .webnovel/
│   ├── state.json      # 空的项目状态
│   ├── index.db        # 空的 SQLite 索引
│   └── vectors.db      # 空的向量库
├── 正文/               # 放章节文件
├── 大纲/               # 放大纲文件
│   └── 总纲.md
└── 设定集/             # 放设定文件
```

然后将第一步准备的文件放入对应目录。

---

## 第三步：逐章构建索引

### 执行命令

从第 1 章开始，按顺序逐章执行：

```bash
/webnovel-write 1 --fast
/webnovel-write 2 --fast
/webnovel-write 3 --fast
...
```

`--fast` 跳过风格适配（Step 2B），但保留所有数据处理步骤。

### 每章会做什么

| 步骤 | 动作 | 产出 |
|------|------|------|
| Step 1 | Context Agent 组装上下文（大纲 + 前章摘要 + 已有实体） | 创作任务书 |
| Step 2A | 检测到章节文件已存在，读取现有正文 | 跳过重写 |
| Step 3 | 六维并行审查（爽点/一致性/节奏/OOC/连贯性/追读力） | `review_metrics` 入库 |
| Step 4 | 润色修复（可按提示跳过） | — |
| Step 5 | **Data Agent 提取** → 实体/关系/状态变更/场景/摘要/向量 | index.db + vectors.db + summaries |
| Step 6 | 更新 state.json 进度 | 章节元数据 |

### 为什么必须按顺序

- 第 N 章的实体消歧依赖前 N-1 章已注册的别名表
- 状态变更链有先后依赖（"斗者→斗师"必须在"斗师→斗王"之前）
- 章节摘要是后续章节 Context Agent 的输入源
- 关系图谱按章节递增构建

### 时间估算

| 章节字数 | 每章耗时 | 30 章总计 |
|----------|----------|-----------|
| ~2500 字 | 2-3 分钟 | ~1-1.5 小时 |
| ~4000 字 | 3-5 分钟 | ~2-2.5 小时 |

主要耗时分布：AI 实体提取（~65%）> 场景切片（~22%）> 向量嵌入（~10%）。

## 第四步：验证索引完整性

```bash
# 查看项目整体状态
/webnovel-query 状态

# 验证核心角色是否被正确识别
/webnovel-query 主角名

# 查看实体关系图谱
/webnovel-dashboard

# 检查项目健康度
/webnovel-query 紧急
```

重点检查：
- 核心角色是否都被识别并归入"核心"或"重要"层级
- 别名是否正确（同一角色的不同称呼是否指向同一实体）
- 关系图谱是否合理
- 状态变更链是否完整

如发现消歧错误（如两个角色的别名搞混），需尽早修正——错误会通过 Context Agent 传播到后续所有章节。

---

## 第五步：开始续写

索引构建完成后，正常使用：

```bash
/webnovel-write 33
```

系统此时拥有前 32 章的完整记忆：实体状态、关系图谱、伏笔追踪、节奏分析，不会"遗忘"已有内容。

## 常见问题

### Q: 导入过程中 Step 4 想修改我的原文怎么办？

Step 4（润色修复）会基于 Step 3 审查结果提出修改建议。如果你不希望修改原文，可以在该步骤提示时选择跳过。

### Q: 章节文件名没有标题怎么办？

系统兼容无标题格式：`第0001章.md`。但建议补上标题，方便后续检索。

### Q: 可以跳过某些章节吗？

不建议。跳过的章节不会被 Data Agent 处理，其中的实体、关系、状态变更都不会进入 index.db，后续章节的上下文会出现断层。

### Q: 导入中断了怎么恢复？

```bash
/webnovel-resume
```

系统会自动检测上次完成到哪一章，从断点继续。

### Q: 大纲来不及写全怎么办？

至少写一个简版总纲和已写章节的一句话章纲。大纲越详细，Context Agent 的上下文质量越高，实体提取和一致性审查的精度也越高。完全没有大纲的情况下，系统仍可运行，但"大纲即法律"这条防幻觉定律将失效。
